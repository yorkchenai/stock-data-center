# 场外基金历史收益与取数验收

## 总回报修复

同批区域性诊断以 `620ac0334f28` 的计算规则为基线。三只基金的空总回报点分别为 27、2 和 31 个。主要原因是部分真实分红日的 `unitMoney` 只有「分红：每10份派现金元」。例如 110017 在 2024-07-18 的公开分红金额是每份 0.040 元，字段缺金额。原解析器把该天标为不可计算，后续任何跨越该日的区间也无法计算。 [基线诊断](https://github.com/yorkchenai/stock-data-center/actions/runs/45125733711/artifacts/14795527377)

- 明确写有每几份、每次分红金额或份额折算比例时，解析为每旧份现金和每旧份折算后总份额。日回报由 `(本日单位净值 × 份额比例 + 每旧份现金) / 上笔单位净值 − 1` 得出。
- 金额为空且来源明确标为现金分红时，可以比较前后两天的「累计净值 − 单位净值」差额。差额必须大于四项净值舍入误差，并且能与同日来源的 `equityReturn` 在限定精度内核对。出现折算后，停止用累计净值推定分红。累计净值保留为原始字段。
- 个别舍入或折算病例以基金管理人披露为证据，按份额代码和除息或折算日精确匹配，将明确金额或比例代入同一公式，再与日报增长率核验。披露证据和来源放在 `stock_analysis/fund_event_evidence.json`，其中没有历史净值序列。
- 源字段缺失、不会解析的事件、无法核对的增长率或无效的净值变化继续保留空值。已有正常日期的增长率核对门槛未扩大。卡片和周期提示通过既有空状态显示首个影响日期和具体原因，统计范围和图表交互保持原样。

披露抽查包括 000001 在 2023-01-12 每份派现 0.0018 元。累计值差额 0.002 元受三位小数显示精度影响。000311 在 2017-08-04、2017-08-15 每份分别派现 0.19 元和 0.15 元。110017 在 2024-07-18 每份派现 0.04 元。161725 在 2020-12-15 的场外份额新增比例为 0.005444122，采用总份额因子 1.005444122。其他缺少精确比例或分红依据的事件保留原缺口。 [华夏成长中报](https://pdf.dfcfw.com/pdf/H2_AN202308301596809497_1.pdf) · [景顺长城经理人年报摘要](https://static.cninfo.com.cn/finalpage/2018-03-28/1204529109.PDF) · [易方达年报](https://cdn.efunds.com.cn/owch/data/bulletin/20250331/%E6%98%93%E6%96%B9%E8%BE%BE%E5%A2%9E%E5%BC%BA%E5%9B%9E%E6%8A%A5%E5%80%BA%E5%88%B8%E5%9E%8B%E8%AF%81%E5%88%B8%E6%8A%95%E8%B5%84%E5%9F%BA%E9%87%912024%E5%B9%B4%E5%B9%B4%E5%BA%A6%E6%8A%A5%E5%91%8A.pdf) · [招商折算公告](https://static.cninfo.com.cn/finalpage/2020-12-17/1208919465.PDF)

## 基估宝与在线实验

| 项目 | 基估宝 | Stock Data Center |
| --- | --- | --- |
| 历史接口 | 同一 `pingzhongdata/{code}.js`，提取 `Data_netWorthTrend`、`Data_ACWorthTrend` 等全量变量 | Python 仅解析 JSON 字面量。隔离实验中两项序列条数与 Python 匹配 |
| 单位净值与分红 | 历史净值区间以相邻单位净值算增长率，正则提取「派现金」后的数。该函数未以每几份为分母，也未处理金额空占位或折算 | 独立验证现金、折算和披露增长率。区间收益使用校验后的总回报路径 |
| 历史并发 | 一次运行一个外部脚本，快照同窗口变量，完成后移除 script 节点。失败不会锁住队列。节点移除后全局变量仍在 | 浏览器本地接口已有同代码在途去重。Python 共享同日目录和同代码正在进行的查询，完成的历史和失败响应不缓存 |
| 缓存及重试 | TanStack Query 的历史键默认新鲜一小时，脚本参数加时间戳。全局客户端最多三次重试，指数退避。失败移除查询 | 保留现有上海自然日目录缓存。已有会话数据保留在页面内，可手动刷新，不自动重试数据源 |
| 批量 | 50 只分块用于实时估值，20 个分块用于板块行情，各自有缓存或在途合并 | 历史接口每个代码一个脚本，保留现有查询机制。估值接口不接入历史研究 |

代码对照固定在参考项目的 `21047dc98272`。 [历史加载与批量逻辑](https://github.com/hzm0321/real-time-fund/blob/21047dc9827213c54be6c570aa52359002c180cf/app/api/fund.js) · [QueryClient](https://github.com/hzm0321/real-time-fund/blob/21047dc9827213c54be6c570aa52359002c180cf/app/lib/get-query-client.js)

从真实 GitHub Pages 站点发起的普通 CORS 请求仍被天天基金目录和历史接口拦截。经典 script 可执行供应商响应，这是另一种浏览器行为。实验在独立 Chromium 上拦截仅测试用的地址，本地提供具有相同 `https://yorkchenai.github.io` 来源的空文档，且每个请求都有不允许同源权限的独立 iframe。生产地址没有注入第三方脚本。三只连续加载、两只并发、模拟加载失败与超时、父文档访问和全局残留分别记录。普通共享窗口的脚本可覆盖全局或遗留上一只基金的数据。Playwright 路由会禁用 HTTP 缓存，实验不用于推断真实浏览器缓存命中率。

沙箱缩小了脚本权限，供应商仍可随时更换执行内容、字段和访问规则，也没有为该请求方式确认公开站点使用授权和可用性承诺。既有部署采用 Python 个人查询与 JSON 导入。 [东方财富协议](https://about.eastmoney.com/home/protocol) · [华夏基金网站声明](https://m.chinaamc.com/protocol/hxjjstatement.html)
